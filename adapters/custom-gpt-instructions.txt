STANDAR TEKNIS YANG WAJIB DITEGAKKAN:
==================================================

1. PEMROGRAMAN AMAN (SECURITY):
- SQL Injection: Dilarang menggabungkan variabel langsung ke dalam raw query. Wajib menggunakan Parameterized Query / Prepared Statements / ORM resmi (contoh: PDO/MySQLi, Node.js/Prisma/pg, SQLAlchemy, PreparedStatement). Jika arsitektur aplikasi belum memungkinkan parameterized query, AI wajib menyarankan mitigasi alternatif: (1) escaping bawaan driver basis data, (2) strict type casting numerik (misal int/parseInt), (3) whitelist array/set validation untuk klausa dinamis seperti ORDER BY, (4) format validation (filter/regex), dan (5) konfirmasi opsi developer.
- XSS Prevention: Parameter input pengguna (misal URL query params) yang dicetak ke HTML wajib disanitasi dengan fungsi encoding/escaping HTML kontekstual (misal htmlentities(), auto-escaping template engine).
- File Download: Wajib berbasis ID dokumen yang terdaftar disertai pengecekan hak akses (otorisasi/role). Dilarang mengekspos path berkas langsung atau parameter nama file di URL.
- File Upload: Nama berkas wajib diubah menjadi hash unik dan divalidasi dengan whitelist ekstensi serta MIME type yang diizinkan.

2. INTEGRITAS & VALIDASI (INTEGRITY):
- Transaksi Database: Setiap proses penulisan data di sisi back end (insert/update/delete) wajib dibungkus blok transaksi dengan penanganan rollback saat error (contoh: PDO/Laravel/CI, Prisma, @Transactional, db.Begin).
- Foreign Key: Wajib mendefinisikan Foreign Key untuk setiap relasi tabel sejak fase ERD.
- Validasi Berlapis: Validasi Back End wajib ada dan diutamakan sebelum Front End (mengantisipasi jika JavaScript dinonaktifkan).

3. ARSITEKTUR & SKALABILITAS:
- URL API & Approval Workflow: Endpoint API dan urutan persetujuan wajib disimpan di database (tidak boleh hardcoded).
- Paging Tabel: Tampilan data bervolume dinamis wajib menggunakan server-side pagination.

4. STANDAR PENAMAAN (NAMING CONVENTION):
- Tabel: Awalan "t_" (contoh: t_transaksi)
- View: Awalan "v_" (contoh: v_rekap)
- Foreign Key: Awalan "fk_<singkatan_tabel>_<nama_kolom>" (contoh: fk_tio_id_invoice_online)
- Function: Awalan "f_", Procedure: Awalan "sp_", Trigger: Awalan "tr_"
- Git Branch: "<kategori>/<nama-modul>/<deskripsi-fitur>" dengan pemisah kata tanda hubung "-" (kategori: feature, develop, qa, release, master, hotfix).

5. DOKUMENTASI (COMMENTING):
Setiap fungsi/prosedur wajib memiliki blok komentar berisi 3 hal:
1. Fungsi: Kode berfungsi untuk apa.
2. Cara Kerja: Alur kerja singkat.
3. Cara Penggunaan: Contoh pemanggilan kode.

6. UI/UX GUIDELINES:
- Form dengan banyak field wajib disusun vertikal (satu kolom ke bawah).
- Pewarnaan Tombol: Submit (Biru), Delete (Merah), Cancel (Pudar/Abu-abu/Putih).
- Navigasi & Logo: Desktop sidebar kiri, mobile web kanan atas, mobile apps kiri atas, logo pojok kiri atas.
- Konsistensi bahasa seragam 100% (Indonesia semua atau Inggris semua).
